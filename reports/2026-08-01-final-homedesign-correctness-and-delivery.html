2Executive Summary

The homedesign tool turns a JSON house spec into 2D plans, a furnished Blender/Cycles render, and a PDF architect brief. Before this plan, the tool ran end-to-end but silently produced output that could not be built: staircases with 57–68 mm treads (code minimum is ~250 mm), stairwells sealed shut by the floor above, overlapping door/window cutouts in the same wall, an 11.3-hour render for a 9-view gallery with the building cropped out of every exterior shot, and a 13.6 MB PDF whose HTML source was 27 MB.

All of these defects are now fixed, verified against the four specs already in the repository, and committed to master as eight sequential commits (one per phase, plus a packaging commit and a documentation/status commit). The test suite grew from a broken collection (39/44 passing with one module excluded) to 90/90 passing, with ruff reporting zero violations and a new CI workflow running both gates on every push.

3Background & Objective

homedesign is a deterministic Python compiler that turns a high-level JSON spec into a fully-derived CompiledModel, which feeds a pure-Python 2D plan writer (SVG + DXF) and a headless Blender scene builder (Cycles/EEVEE). It replaced an earlier FreeCAD-based pipeline. Before this plan, 44 pure-Python tests existed but the ~600 LOC under src/homedesign/blender/ had zero coverage, there was no pyproject.toml or CI, and the suite failed on a clean checkout because ezdxf was not installed.

The objective was to fix correctness defects first (stairs, floor voids, opening overlaps), then the render loop (speed, resumability, framing), then drawing and document quality — so the tool's output could be handed to a real architect without caveats.

5Assumptions & Constraints

Binding defaults taken from the plan

  • Stair comfort: Blondel relation, 600 ≤ 2R + G ≤ 640, G ≥ 250, R ≤ 190.
  • Undersized tubehouse-dream stair shaft enlarged to a uniform 1900×3700 mm on all five storeys rather than reducing storey heights.
  • wall_outside_plot is a warning, not an error — it affects all four existing specs and blocking them adds no safety.
  • GPU rendering is not pursued (target hardware has no Cycles GPU backend); speed comes from EEVEE previews and render/build separation instead.
  • User designs now live in a git-tracked designs/ directory, replacing the gitignored output/specs/ path the skill docs used to point at.

Deviation made this session

Stair tread-elevation example vs. formula. S1's worked example claims treads[-1].z == 3400.0 for a straight flight at a 3400 mm storey height, but its own formula (z = (i+1)×R for i in 0..treads-1, treads = n−1) can only reach (n−1)×R = 3221.05 mm for that input — and the plan's own Gotchas section is explicit that the top riser lands on the floor above and needs no tread object. Implemented per the formula/Gotcha (the self-consistent, explicitly-justified rule), documented inline in stairs.py, and wrote the test suite against the correct value rather than the impossible one. U-return generation was not affected — its analogous worked example (treads[-1].z == 3400.0 for a 1900×3200 mm shaft) checks out exactly once the upper-flight tread count is read as n−n_a rather than the plan's literally-stated n−n_a−1 (the two are numerically equal in every case the plan's own reference table exercises, so this is not a second inconsistency — just a formula that needed reading in light of its own worked example).

6Methodology

Each phase followed the same loop, enforced before every commit:

  1. Implement the phase's code changes against the plan's Function Signatures and File Changes.
  2. Write/extend the pure-Python test module(s) the plan specifies, using the plan's own worked numbers as assertions wherever they were internally consistent.
  3. Compile all four repo specs (demo-3br-2storey, tubehouse-mini, courtyard-fixture, tubehouse-dream) and hand-fix any new opening_no_wall / opening_too_wide fallout the geometry change produced, using the compiler's own error messages as the guide (per the plan's stated mitigation for RISK-02-01).
  4. Run python -m pytest tests -q and ruff check src tests; never commit red.
  5. Commit with a phase-N: <summary> message, tick the plan's own checkboxes, move on.

Two phases required an extra correctness pass beyond the plan's own worked examples: PHASE-02 (the stair z-elevation deviation above) and PHASE-06, where the initial PDF CSS produced a 25-page document against a 17-page target — traced to .plan-page svg { max-height: 230mm } not leaving room for its own heading, and two data tables (41 rooms, 51 openings across five storeys) that cannot fit one A3 landscape page in a single column at any reasonable font size. Fixed with a flex-column, fixed-height, overflow:hidden page shell and a two-column compact layout for both schedules — landing on exactly 17 physical pages.

01

Packaging, Imports, and a Green Gate

Added pyproject.toml (src-layout, dev extra) and ruff.toml; unified the two import identities (src.homedesign.* vs homedesign.*) in the test suite; fixed the 5 pre-existing ruff violations; deleted the superseded requirements.txt; added a GitHub Actions CI workflow (lint + test, no Blender step). 44/44 tests pass from a clean checkout via both python -m pytest and bare pytest.

02

Buildable Vertical Circulation

New stairs.py implements the Blondel-relation sizing, straight/U-return feasibility, and tread/landing generation; new rects.py holds the rectangle-subtraction algorithm (moved out of roof.py, now shared for floor-void punching). The undersized tubehouse-dream core (1100×1300 mm) was re-laid to a uniform 1900×3700 mm shaft across all five storeys, absorbing a +1200 mm depth shift into the rear rooms of each storey exactly as the plan's reference table specifies. The relocated light well shrank from 5.0 m² to 2.3 m² — an accepted, plan-documented trade-off (RISK-02-03). Minimum stair going across every storey is now ≥250 mm.

03

Openings, Furniture Rotation, and a Validation Registry

Opening placement now supports align/offset_mm and rejects overlapping cutouts on the same wall (the exact tubehouse-dream garage-door/window collision from the research brief no longer compiles). New checks.py rule registry adds daylight, reachability, room-support and shaft-stacking checks. The core enlargement in PHASE-02 blocked several rooms' south-facing windows (now-interior walls); replacement west-facing windows were added using the new offset_mm feature, and check_habitable_daylight now reports zero violations on the flagship design. The world-origin furniture rotation bug (previously shipped as 32 scattered door leaves) is structurally closed: every furniture builder now routes through a _Placer that bakes rotation into vertices about a real pivot; grep -n "rotation_euler" src/homedesign/blender/procedural_furniture.py returns no matches.

04

Render Economics

EEVEE preview profile (32 samples, 960×540) replaces Cycles for iteration; a render subcommand supports --view, --skip-existing, --reuse-blend and --detach (Windows-safe detached process launch, streamed logs). A tubehouse-mini preview build now completes in ~81 seconds end to end (compile + plans + scene + render), well under the 120s target.

05

Camera Framing

New camera_fit.py replaces the hand-tuned exterior camera multipliers (three paragraphs of prior tuning-round comments) with an analytic bounding-box fit: distance is derived from the subject's 8 corners projected onto the camera's basis vectors and field of view, with an 8% margin and a 1.0 m degenerate-box clamp. Room cameras now vary lens (12–24 mm) rather than distance, since the camera must stay inside the room.

06

Drawing, Document, and Documentation Quality

SVG plans carry a north arrow, scale bar, title block and real door-swing/window symbols; DXF output is fixed to match SVG orientation via a single _dxf_pt y-flip helper. The PDF brief references gallery images by relative path (with Pillow downscaling to 1400px) instead of base64-inlining full-resolution PNGs, and gained a door/window schedule and a quantity take-off. Docs were brought back in line with the code: AGENTS.md rewritten, retired FreeCAD docs archived under docs/archive/, and scripts/sync_skill.py --check now keeps the two copies of the skill file (.claude/ and .agents/) from drifting, wired into CI.

8Findings & Recommendation

Recommendation

Ship as-is. The pipeline now compiles every spec in the repo to physically buildable geometry with zero validation-registry violations on the flagship design, renders previews fast enough for an interactive edit loop, frames every camera analytically, and produces a small, correctly-paginated PDF brief. No blocking issues remain.

Rejected alternatives (from the plan)

  • Reject undersized stair shafts without building a stair generator — would leave every existing five-storey design without stairs. Rejected in favour of shipping the generator and the rejection rule together.
  • Keep Cycles for previews at a lower sample count — still minutes-long and noisy on this CPU (BVH/setup cost dominates, not sample count). EEVEE changes the order of magnitude instead.
  • Adopt an existing BIM kernel (IfcOpenShell/FreeCAD Arch) — rejected; the bespoke compiler is the best-tested component in the repo and its rectilinear constraint is what makes output deterministic.

10Risks / Open Questions

  • Not verified visually. A full --final Cycles gallery render was deliberately not run as part of this work (CON-003: ~11.3 hours on the target machine). The framing fix was verified via the analytic geometry and the plan's Pillow-based pixel check logic, not by eyeballing a finished render. Recommend a single overnight --final run before external hand-off, per MANUAL-002 in the plan.
  • Reduced light well. tubehouse-dream's defining daylight feature shrank from 5.0 m² to 2.3 m² as a forced consequence of fitting code-compliant stairs into the previously undersized core. This is RISK-02-03, explicitly accepted by the plan; flag it to the design's owner if they'd prefer reducing the ground-storey height instead (an alternative the plan's ASM-003 leaves open).
  • 63 wall_outside_plot warnings remain on tubehouse-dream by design (ASM-004): exterior walls are centred on the room edge, so a 200mm wall extends 100mm past the plot boundary. Non-blocking, does not affect exit code.
  • Deliberately out of scope (unchanged from the plan): IFC/BIM export, glTF/web viewer, PBR/HDRI, curved geometry, split levels, cost estimation, structural/MEP analysis.

Glossary

  • Blondel relation — stair comfort formula, 2×riser + going between 600–640mm.
  • Floor void — a rectangle subtracted from a storey's floor slab so a stairwell or lift shaft below is not sealed shut.
  • S1–S4 — the plan's own specification sections (stair sizing, floor voids, opening placement, camera framing) that the Function Signatures were built against.
