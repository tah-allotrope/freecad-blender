01 / Executive Summary

Executive Summary

What was wrong

The renders were trustworthy but the drawings were not: every room's authored name was dropped by the compiler, the north and south elevations of the flagship design were empty sheets, and the PDF's STALE badge was computed per image but rendered per page.

What was built

Six phases: room names + XML-safe writers + per-image staleness; a real orthographic elevation projection; declared floor voids, rooftop structures and four new room types; boolean-free wall geometry; dimension chains, numeric levels and spec-driven section cuts; and the full deliverable path (brief --init, --out, publish, site.north_deg).

Headline result

204 passing tests (up from 134), ruff clean, skill mirror in sync. The contractor's north elevation went from a bare outline to a ~37 KB facade with walls, openings and parapets; the mezzanine void is declared, not faked.

The honest caveat

The plan's furniture-coverage target (55/62) is unachievable: stairwell and elevator shafts are unfurnished by design, capping the flagship at 47/61. Measured coverage is 35/61 — a real gain from 19/62, recorded rather than hidden.

02 / Background & Objective

Background & Objective

The third-pass brainstorm (research/2026-08-14-homedesign-third-pass-brainstorm.md) framed the problem precisely: the 3D half of the pipeline had become trustworthy, but the 2D half — the half an architect and contractor build from — was silently producing blank, unlabelled drawings, and nothing in 134 tests noticed. The flagship's own fidelity ledger named the ceiling: the spec could not say "void", so a fake SÀN GIẢ room was authored to pass a checker.

The objective was the six-phase plan: land room names safely, project real elevations, let the spec declare voids and rooftop structures, build walls without booleans, dimension the drawings, and remove the manual steps between a compiled design and a shippable deliverable.

Out of scope

  • Curved/non-orthogonal geometry, split levels, IFC export.
  • Textures, UVs, HDRI, a downloaded asset library, GPU rendering.
  • Changing the Blender version or render-engine selection; redesigning either house.

Decisions

  • Elevations rewritten, not patched (the coplanarity definition was wrong, not the tolerance).
  • Voids belong on the storey (storeys[].voids[]), not as a room type.
  • Legacy EEVEE stays pinned; bpy tests are optional, never in CI.
04 / Methodology

Methodology

The plan was executed phase-by-phase, each verified to its own exit criteria before the next began. PHASE-01 propagated rooms[].name through both compiler branches and added a single xml.sax.saxutils.escape helper used by every SVG/HTML text site. PHASE-02 replaced the plot-coplanarity wall filter with a true orthographic projection (all walls, openings, parapets, treads, roof polygons, painter-sorted). PHASE-03 grew the schema (voids, structures, four room types) and re-authored the flagship. PHASE-04 moved wall geometry into pure rects.subtract_rects and deleted the boolean solver. PHASE-05 added dimension chains and numeric levels. PHASE-06 added brief, --out, publish and north_deg, plus furniture for the empty room types.

06 / Findings & Recommendation

Findings & Recommendation

The defects were real, and each is now regression-pinned.

  • Dropped names — compile_spec now returns BẾP & ĂN, and a test with an &-bearing name proves the SVG still parses.
  • Blank elevations — the north/south elevation test fails on the old code and passes now, because the plane test was replaced by a projection over every wall.
  • Last-image-wins STALE — a mixed stale/fresh page now shows exactly one per-image badge.
  • The "void" ceiling — the spec can declare a beam-spanned opening; the checker is stricter, not weaker, and the fake SÀN GIẢ room is gone.

Recorded deviations from the plan's own targets

Three plan targets were internally inconsistent and are recorded rather than hidden: two pre-existing elevation tests were updated to match the (correct) new behaviour; the dimension-chain example assumed a ground floor without the lift lobby split; and the furniture-coverage target exceeded what the shaft rooms make possible.

Recommendation

Ship it. The 2D set is now as trustworthy as the renders. Treat the remaining gap — blender/ furniture coverage and the plan's own verify subcommand suggestion — as the next pass.

07 / Risks / Open Questions

Risks / Open Questions

Risks

  • Elevation bloat: projecting every wall grows the SVG; the PDF inliner was left with headroom and the brief HTML stayed within budget.
  • Hash churn: PHASE-03/05 change the flagship model hash, so old renders are stale until the final re-render + publish — completed this pass.
  • Blender-side tests: they run only where bpy is installed; CI skips them by design.

Open questions

  • Should the light well be modelled as a true multi-level shaft (it is currently only renamed, not cut)?
  • Should a homedesign verify subcommand promote the hand-run invariants into the tool?
  • Should furniture coverage extend to stairwell/elevator (the 14 rooms that cap the target)?
